# Бухгалтерия боссов офиса — API для фронтенда

Модуль учёта расходов офиса между тремя боссами-совладельцами. Каждый босс
владеет долей бизнеса в процентах. Все расходы офиса делятся между боссами
пропорционально их долям, а если расход реально оплатил один босс — доли
остальных превращаются в долг перед ним.

Backend: Django REST Framework. Приложение: `apps/boss`.

---

## 1. Термины

| Термин | Что это |
|---|---|
| **Boss** (босс) | Совладелец бизнеса. Есть `share_percent` — доля в офисе, %. Сумма долей всех активных боссов должна быть равна 100. |
| **OfficeExpense** (расход офиса) | Реальный платёж за офис (аренда, коммуналка, ремонт и т.д.), который кто-то из боссов оплатил из своего кармана. |
| **Debt** (долг) | Автоматически создаётся при добавлении расхода: доля каждого босса (кроме оплатившего) от суммы расхода становится его долгом перед оплатившим. |
| **DebtSettlement** (погашение) | Запись о том, что должник вернул (полностью или частично) деньги по долгу. |

---

## 2. Как работает распределение (ключевая механика)

Пример из ТЗ: три босса, доли ≈ 33.3333% / 33.3333% / 33.3334%. Офис "в
минусе", и Босс А оплачивает расход на 6600 сом.

1. Система делит 6600 сом по долям: 2200.00 / 2200.00 / 2200.00.
2. Доля самого Босса А (2200.00) — это **его собственный расход**, никакого
   долга по ней нет.
3. Доли Босса Б и Босса В (по 2200.00) становятся их **долгом перед
   Боссом А** — то есть Босс А как бы одолжил им эти деньги.

Итого после одного такого расхода: Босс А потратил 6600, из них реально
"его" — 2200, а 4400 — это его требования (дебиторка) к партнёрам.

Это происходит **автоматически** при создании `OfficeExpense` — фронтенду
ничего специально вызывать не нужно, достаточно создать расход с полем
`paid_by`.

**Почему доля хранится с 4 знаками после запятой, а не с 2.** 100% на
3 боссов не делится ровно: при точности в 2 знака пришлось бы делать
33.33 / 33.33 / 33.34 (сумма 100.00, но доли не равны), и при делении
крупных сумм третий босс регулярно получал на десятки копеек больше
остальных. С 4 знаками (33.3333 / 33.3333 / 33.3334, сумма 100.0000)
такое расхождение почти всегда укладывается в 1 копейку — предел, ниже
которого делить деньги физически невозможно. При вводе доли на фронте
используйте `step="0.0001"` (не `0.01`) в поле `share_percent`, иначе
браузер заблокирует отправку значений вроде `33.3333`.

**Округление.** Итоговые суммы долгов всегда считаются в копейках. Чтобы
сумма долей всегда точно равнялась сумме расхода, остаток от округления
уходит последнему боссу по `id`. Если сумма расхода не делится ровно между
боссами (например, не кратна количеству боссов) — расхождение в 1 копейку
между должниками возможно и это ожидаемое поведение, не баг.

**Погашение долга.** Когда должник возвращает деньги оплатившему боссу
(наличными/переводом вне системы), это фиксируется через
`POST /debts/{id}/settle/`. Можно гасить долг частями.

**Важно:** если по долгам расхода уже было хотя бы одно погашение,
изменить сумму/плательщика этого расхода или удалить его нельзя — API
вернёт `400`. Нужно сначала аннулировать погашения (в этой версии API это
делает администратор напрямую в БД/админке) либо оформить новый
корректирующий расход.

## 3. Авторизация

Все эндпоинты требуют аутентификации (`IsAuthenticated`). Поддерживается
Token-авторизация:

```
Authorization: Token <ключ_из_/api/v1/api/auth/login или из TokenAuth>
```

> В проекте сейчас включён `rest_framework.authentication.TokenAuthentication`
> (см. `core/config_drf.py`). Получить токен можно через существующий
> эндпоинт логина (`apps/account`), уточните у бэкенда актуальный путь
> логина, который вы используете в проекте.

## 5. Боссы — `/api/v1/bosses/`

### `GET /bosses/`
Список боссов. Query-параметры: `is_active=true|false`,
`search=<имя или телефон>`, `ordering=name|share_percent|create_dt`
(с `-` для убывания).

```json
{
  "count": 3,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": 1,
      "name": "Босс А",
      "phone": null,
      "share_percent": "33.3333",
      "is_active": true,
      "create_dt": "2026-09-03T13:12:27+06:00",
      "update_dt": "2026-09-03T13:12:27+06:00"
    }
  ]
}
```

### `POST /bosses/`
Создать босса. Body: `{ "name": "Босс А", "phone": "+996700000000", "share_percent": "33.3333", "is_active": true }`.
`phone` необязателен.

### `GET / PATCH / DELETE /bosses/{id}/`
Обычный CRUD.

### `GET /bosses/{id}/summary/?date_from=&date_to=`
Отчёт по одному боссу. `date_from`/`date_to` необязательны (формат
`YYYY-MM-DD`), фильтруют расходы по дате.

```json
{
  "boss": { "id": 1, "name": "Босс А", "share_percent": "33.3333", ... },
  "total_paid": "100.00",
  "total_obligation": "33.33",
  "balance": "66.67",
  "owed_to_him": "33.34",
  "owes_to_others": "0.00",
  "net_debt_balance": "33.34"
}
```

Что означают поля:

- **total_paid** — сколько босс реально отдал денег за офис (сумма всех
  расходов, где `paid_by = этот босс`) за период.
- **total_obligation** — сколько он "должен был" отдать по своей доле от
  **всех** расходов офиса за период, независимо от того, кто платил.
- **balance** = `total_paid - total_obligation`. Положительное число —
  босс переплатил (профинансировал офис больше своей доли), отрицательное
  — недоплатил.
- **owed_to_him** — сколько ему сейчас должны другие боссы (непогашенные
  долги, где он кредитор).
- **owes_to_others** — сколько он сейчас должен другим (непогашенные
  долги, где он должник).
- **net_debt_balance** = `owed_to_him - owes_to_others` — фактическое
  текущее сальдо по долгам (с учётом уже возвращённых денег).

`balance` — это исторический показатель "переплатил/недоплатил по
расходам за период" и не меняется, когда долги гасятся. `net_debt_balance`
— это живой остаток по факту прямо сейчас. Для UI: `balance` подходит для
графика "кто сколько вложил за месяц", `net_debt_balance` — для карточки
"кто кому должен сейчас".

### `GET /bosses/report/?date_from=&date_to=`
Сводный отчёт по офису: сумма всех расходов за период, сумма долей всех
активных боссов (должна быть 100 — если не так, стоит показать
предупреждение на фронте) и `summary` по каждому боссу (тот же формат,
что и выше).

```json
{
  "date_from": null,
  "date_to": null,
  "total_expenses": "100.00",
  "shares_total_percent": "100.00",
  "bosses": [ { "boss": {...}, "total_paid": "...", ... }, ... ]
}
```

## 6. Расходы офиса — `/api/v1/office-expenses/`

### `GET /office-expenses/`
Фильтр "какой босс сколько отдал" делается через `?paid_by=<id_босса>`.

Query-параметры:
- `paid_by` — id босса (кто оплатил)
- `category` — `rent | utilities | repair | supplies | salary | other`
- `date_from`, `date_to` — `YYYY-MM-DD`
- `search` — поиск по названию/описанию
- `ordering` — `date | amount | create_dt` (с `-` для убывания)
- пагинация: `page`, `limit`

```json
{
  "count": 1,
  "results": [
    {
      "id": 1,
      "title": "Аренда",
      "description": null,
      "category": "other",
      "category_display": "Другое",
      "amount": "100.00",
      "date": "2026-09-01",
      "paid_by": 1,
      "paid_by_name": "Босс А",
      "create_dt": "...",
      "update_dt": "..."
    }
  ]
}
```

Чтобы получить сумму, отданную конкретным боссом за период, проще всего
использовать `GET /bosses/{id}/summary/?date_from=&date_to=` (поле
`total_paid`) — там уже посчитана агрегация. Список расходов через
`?paid_by=` нужен, когда требуется именно перечень платежей (детализация),
а не только итоговая сумма.

### `POST /office-expenses/`
Создать расход (боссы автоматически рассчитаются как долг остальным).

```json
{
  "title": "Аренда за сентябрь",
  "description": "необязательно",
  "category": "rent",
  "amount": "15000.00",
  "date": "2026-09-01",
  "paid_by": 1
}
```

При успехе — сразу создаются связанные `Debt` для остальных боссов
(смотрите пункт 7).

### `PATCH /office-expenses/{id}/`
Изменение расхода (сумма/категория/плательщик и т.п.) пересчитывает
долги заново. **Заблокировано**, если по старым долгам этого расхода уже
было погашение — вернётся:
```json
{ "amount": ["Нельзя изменить этот расход: ..."] }
```
(ошибка приходит как `400 Bad Request`, текст — на русском, можно
показывать пользователю как есть).

### `DELETE /office-expenses/{id}/`
Удаляет расход и его долги. Тоже заблокировано, если были погашения —
вернётся `400` с `{ "detail": "Нельзя удалить этот расход: ..." }`.

## 7. Долги между боссами — `/api/v1/debts/`

Только чтение + действие погашения (создаются автоматически, вручную
через API не создаются).

### `GET /debts/`
Query-параметры: `debtor=<id>`, `creditor=<id>`, `is_settled=true|false`,
`source_expense=<id_расхода>`, `date_from`, `date_to` (фильтр по дате
создания долга).

```json
{
  "results": [
    {
      "id": 1,
      "debtor": 2,
      "debtor_name": "Босс Б",
      "creditor": 1,
      "creditor_name": "Босс А",
      "source_expense": 1,
      "amount": "33.33",
      "repaid_amount": "10.00",
      "remaining_amount": "23.33",
      "is_settled": false,
      "settled_at": null,
      "settlements": [
        { "id": 1, "debt": 1, "amount": "10.00", "date": "2026-09-02", "comment": "частично", "create_dt": "..." }
      ],
      "create_dt": "..."
    }
  ]
}
```

Полезные представления для UI:
- **"Кто кому должен"** — `GET /debts/?is_settled=false`, сгруппировать
  по `debtor_name` → `creditor_name`.
- **"Долги конкретного босса"** — `GET /debts/?debtor=<id>&is_settled=false`.
- **"Кому должны вернуть"** — `GET /debts/?creditor=<id>&is_settled=false`.

### `POST /debts/{id}/settle/`
Зафиксировать погашение (полное или частичное).

```json
// запрос
{ "amount": "23.33", "date": "2026-09-03", "comment": "остаток наличными" }
```
```json
// ответ — обновлённый Debt (см. формат выше), с новым settlements[]
```

Ошибки: сумма ≤ 0 или больше `remaining_amount` → `400`
`{ "detail": "Сумма погашения превышает оставшийся долг." }`.

## 8. Категории расходов

```
rent       — Аренда
utilities  — Коммунальные услуги
repair     — Ремонт
supplies   — Хозтовары
salary     — Зарплата персонала
other      — Другое
```
(значение — то, что отправлять в `category`; `category_display` в ответе
— готовый текст для UI на русском).

## 9. Рекомендуемые экраны фронтенда

1. **Список боссов** с их долями и `net_debt_balance` (цветом: зелёный —
   ему должны, красный — он должен).
2. **Расходы офиса** — таблица с фильтром по боссу (`paid_by`), категории
   и периоду; кнопка "Добавить расход".
3. **Карточка босса** — сводка из `/bosses/{id}/summary/`: сколько отдал,
   сколько его доля, баланс, кому должен / кто должен ему.
4. **Долги** — список непогашенных долгов с кнопкой "Погасить"
   (открывает форму: сумма, дата, комментарий → `POST /debts/{id}/settle/`).
5. **Общий отчёт по офису** — `/bosses/report/` за выбранный период, с
   предупреждением, если `shares_total_percent != 100`.

## 10. Технические заметки для бэкенда (справочно)

- Все денежные суммы — строки с 2 знаками после запятой (Decimal), не
  числа с плавающей точкой — не конвертируйте через `parseFloat` без
  необходимости, для отображения используйте как строку.
- Текущая БД в проекте — SQLite (dev). Для продакшена уже подготовлен
  закомментированный конфиг PostgreSQL в `core/database.py` — для
  денежных расчётов рекомендуется перейти на него до продакшена.
- Swagger/Redoc уже подключены в проекте (`drf_yasg`), доступны по
  `/api/v1/swagger/` — там будет автоматическая схема всех полей и
  методов, этот документ — дополнение с объяснением бизнес-логики,
  которую свагер не показывает.
